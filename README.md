# Community Health Clinic Appointment Management System

## 1. Project Description

The Community Health Clinic Appointment Management System is a simple console-based application developed using the Dart programming language.

The system helps clinic staff register patients, book appointments, and view patient and appointment records.

## 2. Project Objectives

- To register patients and record their details.
- To book appointments for patients.
- To display registered patients.
- To view appointment details.
- To practise basic Dart programming concepts.

## 3. Technologies Used

- **Programming Language:** Dart
- **Development Environment:** Dart SDK or a Dart-compatible IDE
- **Version Control:** Git and GitHub

## 4. System Features

1. **Patient Registration:** Records the patient's name, age, and phone number.
2. **Appointment Booking:** Records the patient's name, doctor's name, appointment date, and time.
3. **View Appointments:** Displays all appointments recorded during the current session.
4. **View Registered Patients:** Displays registered patient information.
5. **Input Validation:** Checks required fields and validates the patient's age.
6. **Exit:** Allows the user to close the application.

## 5. Requirements

- A computer.
- Dart SDK installed.
- A code editor such as Visual Studio Code or Android Studio.

## 6. How to Run the Program

1. Install the Dart SDK.

2. Create a project folder named `community_health_clinic`.

3. Create a file named `main.dart`.

4. Copy the Dart source code into `main.dart`.

5. Open a terminal in the project folder.

6. Run the following command:

   ```bash
   dart martin.dart
   ```

7. Follow the menu instructions displayed in the terminal.

## 7. How to Use the System

When the program starts, it displays a menu with the following options:

- Option 1: Register Patient
- Option 2: Book Appointment
- Option 3: View Appointments
- Option 4: View Registered Patients
- Option 5: Exit

Enter the number corresponding to the operation you want to perform.

## 8. Limitations

The current version stores information temporarily in memory. Patient and appointment records are lost when the program closes. The system does not yet include user login, a permanent database, or automatic doctor availability checking.

## 9. Future Improvements

Future versions could include a database, secure user accounts, appointment cancellation, appointment rescheduling, doctor availability checking, and a graphical user interface.
